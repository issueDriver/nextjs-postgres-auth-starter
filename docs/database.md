# 数据库迁移与 Schema

设计依据：[技术文档](./tech.md)。SQL 迁移是数据库结构的权威来源，Drizzle 映射位于 `lib/db/schema.ts`。应用不再在登录请求中临时建表。

## 1. 命令与连接

在项目根目录运行，使用与 Next.js 一致的环境文件加载规则；已存在的进程环境变量优先。

```bash
pnpm db:check
pnpm db:status
pnpm db:backup
pnpm db:migrate
```

- `db:check`：只读检查 PostgreSQL 版本、业务表行数、账号异常数量、JSON 包装分类、已初始化词序与迁移状态，不输出账号内容或凭证。发现账号或词序异常时返回非零状态。
- `db:status`：只读查看迁移是否已应用，并核验已应用文件的校验和。
- `db:backup`：只读保存本次初始化会改写的书籍 `wordCount/updatedAt` 元数据到被 Git 忽略的 `backups/`，不包含连接凭证，文件权限为仅当前用户读写。这不是完整数据库备份，不能替代托管备份。
- `db:migrate`：在单个事务中执行所有待应用迁移，并记录版本、文件名、SHA-256 校验和及执行时间。

应用使用 `POSTGRES_URL`；迁移优先使用 `MIGRATION_DATABASE_URL`，未设置时使用 `POSTGRES_URL`。建议迁移使用受控直连身份，应用使用权限更小的运行身份。命令输出的目标指纹可用于确认多次命令连接同一目标，不输出真实连接地址。

已有 URL 查询参数和 `sslmode` 保持不变。未显式指定 SSL 模式时，远程连接要求 TLS，localhost/loopback 允许本地无 TLS。不要在 URL 中重复追加问号。

## 2. 迁移内容

| 版本 | 内容 |
| --- | --- |
| `0001_auth_and_study_schema.sql` | 兼容已有 books/words，空库可创建基线；创建或约束 User；增加 studyVersion、sortOrder、studyOrder；建立用户词书进度表及索引/外键 |
| `0002_initialize_study_order.sql` | 按 wordRank NULLS LAST、数据库 ID 初始化连续词序，过滤非法词头，校准有效 wordCount，校验连续性 |
| `0003_optional_study_tracking.sql` | 预建逐词进度、学习会话和学习事件三表，暂不接入业务、不回填数据 |

原有词库列、JSON 内容、账号 ID、邮箱与密码哈希不会被替换。词书标题、状态、封面与 tags 保持原值；`wordCount` 会校准为有效学习词数，`updatedAt` 随初始化更新。

`User` 延续现有 integer 主键；`words.id` 保持 bigint identity；`content` 保持 json。API 后续需要将 bigint 转换为字符串，不能转成 JavaScript Number。

新增 `user_book_progress` 使用 `(user_id, book_id)` 主键，保存已确认的连续前缀数量、末词 ID、版本、总数快照、revision 和时间。数据库约束防止越界、跨书末词和错误完成状态；是否正好确认当前待学词仍需未来学习服务事务校验。

`0003` 仅创建以下预留表和关联索引，不会重跑初始化或变更现有进度：

| 表 | 预留用途 |
| --- | --- |
| `user_word_progress` | 用户在某书某词上的状态、学习次数及时间；联合主键为用户、词书、单词 |
| `study_sessions` | 一次学习的开始/结束、状态和本次已学数量，不是认证 session |
| `study_events` | 学习操作类型、发生时间、可选单词和会话，以及对象类型 payload |

这些表创建后保持为空，没有自动写入触发器。当前学习进度仍只以 `user_book_progress` 为准。单词关联使用 bigint，事件与会话通过包含用户、词书、版本的复合外键关联，避免串号或串书。删除用户会清理其预留明细；删除会话会清理该会话事件；原词书与单词不能在有引用时直接删除。

内部表 `public._schema_migrations` 仅管理迁移版本，不是学习业务表。不要手动增删其记录来绕过检查。

账号、进度、会话、事件和迁移管理表撤销 PUBLIC 以及存在时的 `anon/authenticated` 直接权限，避免托管服务默认授权暴露私有数据；原 books/words 权限不变。独立应用数据库角色应由管理员显式授予必需表和序列权限，不能使用前端公开角色执行服务端认证。

## 3. 执行保护与失败处理

- 首次执行前备份现有数据库，并在维护窗口运行；初始化会锁定相关表写入。
- 全部待应用版本在同一事务执行，任一失败即回滚本次 DDL、回填和迁移记录，不留下半套结构。
- 使用事务级 advisory lock 防止同一数据库多个迁移进程同时运行。
- 锁等待上限 10 秒，单条语句上限 120 秒；大词库需先在测试环境评估维护时间。
- 账号空邮箱、空哈希或规范化邮箱重复时中止，只报告异常数量，不自动删除、合并或重写账号。
- 初始顺序回填发现已有任意学习进度时中止，不重排用户正在学习的书。
- 同一词书中相同或缺失 rank 由 ID 稳定排序；SQL 只将字符串类型的 JSON 词头作为候选。
- 已应用迁移校验和不匹配、文件缺失或版本顺序异常时中止；新改动应新增版本，不修改历史 SQL。
- 数据库错误日志只输出安全错误码。失败后先运行 `db:check`，在数据库管理端按权限检查问题，勿把含行数据的原始错误复制到公开日志。

如果现有结构与文档基线不同，迁移应失败并调查差异，不使用 ORM push 自动删除或重建表。更不能通过删除版本记录来强制重跑。

## 4. 验证与测试

```bash
pnpm test:db
pnpm typecheck
pnpm lint
```

数据库测试使用独立的 PGlite PostgreSQL WASM 实例，不加载 `.env`，不会连接开发或生产数据库。覆盖空库、已有数据保留、非法词头、rank 重复/空值、大 bigint、约束、账号预审计、版本重复执行、校验和和事务回滚。

PGlite 使用真实 PostgreSQL SQL 引擎，但它不替代真实多连接数据库的并发/连接池验收。上线前还需在测试 PostgreSQL 上验证迁移锁等待、权限、SSL 与实际数据规模。

迁移完成后再次运行 `db:status` 应全部显示 applied；再次运行 `db:migrate` 应提示已是最新版本，不重写词序。

## 5. 后续迁移与恢复

新增变更创建新的四位版本 SQL 文件，按顺序提交代码及对应 schema 映射。历史文件按 LF 计算校验和，CRLF 不造成无意义的版本漂移。

不提供自动 down 命令。应用回退时保留新列和真实进度；有数据后不得通过 DROP、TRUNCATE 或重跑初始化恢复旧结构。需要修复词序、内容或版本时使用明确的数据迁移，必要时从受控备份恢复。

发布后的书内词序和内容应冻结。后续导入新书属于独立发布流程，本次一次性初始化脚本不是日常导入工具。
